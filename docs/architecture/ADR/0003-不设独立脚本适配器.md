# ADR-0003: 不设独立"脚本适配器"

## Status
Accepted

## Context
项目当前有三个"调用面"的既视感：
- Web 控制台（给人，浏览器 owner + API server）
- CLI（给 AI Agent，纯 HTTP 客户端）
- 独立脚本 `match_report.py`（批处理 / 定时跑报告）

但实测：CLI 与脚本在架构上是同一件事——都是 HTTP 客户端调 Web API。
脚本的特殊性只是"运行模式"（非交互、长运行、本地产物如报告文件），不是"新能力集合"。

若把脚本列为第三个适配器，就要多维护一份能力矩阵 / 命令注册 / 文档，
会重演 README / SKILL / schema 三处命令数漂移的老路。

## Decision
**不设独立"脚本适配器"。** 批处理 / 定时任务只是 CLI 的"脚本模式"：
- 交互模式（默认）：人 / Agent 实时输入，`lakejob collect --city 武汉`
- 脚本模式：定时 / 批处理，`lakejob batch market-report`、cron、`automation_update`
  本地只跑**非浏览器**逻辑（调 API 拿数据后 import `core/report.py` 生成报告，读 SQLite，不开浏览器）

`match_report.py` 废弃，能力下沉 `core/report.py`，入口改为 `lakejob batch market-report`。
`scripts/`（一次性维护脚本如 `refine_search_kw.py`）保持独立，不纳入适配器。

## Consequences
- 正面：调用面收敛为 web + cli 两个，维护面减半，漂移面收窄。
- 负面：批处理场景需在 CLI 增加 `batch` 子命令壳（P2），且依赖 Web 控制台运行（见 ADR-0001）。
- 约束：CLI 脚本模式绝不自己开浏览器，浏览器需求一律经 Web API 委托。
