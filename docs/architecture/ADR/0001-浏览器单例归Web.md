# ADR-0001: 浏览器（Firefox profile）单例归 Web 控制台独占

## Status
Accepted

## Context
BOSS 直聘的浏览器操作依赖一个 Firefox profile（登录态、cookie）。当前存在多个调用面会触发浏览器：
- Web 控制台（`boss_app.py`）自己 import `boss_firefox` 直接驱动；
- 独立脚本 `match_report.py` 也自己 import `boss_firefox` 直接驱动；
- CLI 是纯 HTTP 客户端，不直接开浏览器。

Firefox profile 不能同时被两个进程持有，否则登录态互相踩、点击错乱、数据污染。
现状中 Web 与脚本不能同时跑（项目记忆已记载），互斥死结一直没解开。

## Decision
浏览器单例**唯一 owner 是 Web 控制台进程**。CLI（含脚本模式）绝不自己开浏览器，
所有浏览器相关操作（采集、投递、聊天监控）一律委托运行中的 Web 控制台（经 API）。
独立脚本 `match_report.py` 废弃，其批处理能力改走 CLI 脚本模式 → Web API（决策③）。

## Consequences
- 正面：互斥死结彻底解开；多调用面可安全并发提交任务（配合 ADR 后续浏览器操作锁）。
- 负面：CLI / 脚本执行浏览器操作前必须确保 Web 控制台在运行；需 P2 实现浏览器操作锁做并发排队。
- 约束：core 层的 `scrape.py` 只在 Web 进程内被真正实例化，CLI 只发 API 请求。
