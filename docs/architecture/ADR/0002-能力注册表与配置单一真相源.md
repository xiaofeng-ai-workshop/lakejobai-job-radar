# ADR-0002: 能力注册表 + 配置 单一真相源

## Status
Accepted

## Context
项目长期存在文档 / 调用面漂移：
- 命令数 README 写 18、SKILL 写 16、schema 14、代码实际 20；
- 版本号 README / SKILL / 后端三处各自为政；
- 配置来源不一致：AI Key 已不回显（v4.2），但设置项散在 `settings` 表 + env，
  CLI 用 env、Web 用表，两套来源易冲突。
- `smart_send` / `company_preview` 在 CLI 与 schema 里被宣称，后端无路由（死链）。

根因：没有单一真相源，能力清单、命令、API、配置、版本都是各处手搓。

## Decision
1. **能力注册表** = `core/capabilities.py`：定义全部能力（§3.1）与 CLI 命令级注册表，作为唯一真相源。
   Web / CLI / README / SKILL / schema 都由它派生，禁止在别处手搓。
2. **配置单一真相源**：运行时以 `settings` 表为权威；env 仅作为启动注入 / 回退。
   同一配置项不再允许 CLI 读 env、Web 读表导致两边值不同。
3. **版本号单一真相源**：以 `pyproject.toml` 为准（P4 起由脚本读取生成文档）。

## Consequences
- 正面：命令数 / 描述 / 版本 / 配置一处定义、处处一致；死链在注册表标记 `status=dead_link`，
  下架只需改生成开关，不再漏删。
- 负面：所有调用面与文档改为「读注册表」而非自带副本，需 P0 落地注册表、P3/P4 切换引用方。
- 约束：`core/capabilities.py` 与 `core/config.py` 不得 import 任何适配器，保持纯 core 层。
