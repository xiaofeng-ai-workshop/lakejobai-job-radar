# 📖 使用指南（新手向）

> 目标读者：第一次接触本项目的用户。跟着走一遍就能跑通：**指定城市 + 岗位关键词 → 采集 JD → 出匹配报告 / 投递**。
> 已经了解项目的同学请直接看 [README](../README.md)。

## 一、这个工具能干什么（能力地图）

本工具有两种使用方式，能力各有侧重：

| 能力 | Web 控制台（浏览器点选操作） | 命令行脚本 |
|------|:--:|:--:|
| 指定城市+岗位搜索 | ✅ | ✅ |
| 批量采集 JD 全文入库 | —（只存卡片信息） | ✅ match_report.py |
| 简历-JD 匹配度排序报告 | — | ✅ match_report.py |
| 关键词缺口分析（简历该补什么词） | — | ✅ match_report.py |
| 一键批量投递 + 每日上限 | ✅ | ✅ |
| AI 分析单个岗位 / 简历优化建议 | ✅ | 部分 |
| 聊天接管 / AI 自动回复 / 交换微信 | ✅ | 部分 |
| 面试刷题（interview 子模块） | — | ✅ |

**简单说**：想看报告、分析匹配度 → 用命令行 `match_report.py`；想日常投递、聊 HR → 用 Web 控制台。两者共用同一份登录态和数据库，可以混着用。

### AI Key 对各功能的影响（先看这个）

本项目的基础功能**都不依赖 AI**（搜索、采集、投递、聊天记录、报告统计）；AI Key 只增强"需要智能生成/判断"的环节。逐项说明：

| 功能 | 需要 AI Key？ | 不配 Key 时的降级行为 |
|------|:--:|------|
| 搜索 / 采集 JD / 入库 | ❌ 不需要 | 完整可用 |
| 投递（固定模板招呼语） | ❌ 不需要 | 完整可用 |
| 投递（智能招呼语，设置里 greeting_mode=smart） | ✅ 影响 | 自动回退固定模板，投递本身不受影响 |
| 匹配报告 · 市场热词统计 | ❌ 不需要 | 完整可用（纯本地词频统计） |
| 匹配报告 · 逐岗智能打分 | ✅ 影响 | 降级为关键词覆盖率打分（分数粗一些，报告结构不变） |
| Web「AI 分析岗位」按钮 | ✅ 必须 | 按钮报错"AI分析失败"，其他功能不受影响 |
| Web「AI 简历优化 / 沟通建议」 | ✅ 必须 | 同上，不可用但不影响其他 |
| AI 自动回复（聊天接管） | ✅ 必须 | 无法开启，需手动回复 |
| 面试刷题 · 出题 | ⚠️ 需本地 Ollama（不是 API Key） | 不装 Ollama 无法出题 |
| 面试刷题 · 批改 | ✅ 必须（DeepSeek Key） | 无法批改 |

> "影响"= 该功能需要 Key 才有完整体验，没 Key 时走降级路径；"必须"= 没 Key 该功能直接不可用。
> 配置入口：Web 控制台「设置」→ AI 模型配置（支持 DeepSeek / OpenRouter / MiMo）。**注意：配了 Key 后，简历摘要/聊天上下文会发送给对应服务商**——介意隐私可以不配，基础功能完全够用。

## 二、安装（只做一次）

在项目根目录打开终端（cmd 或 PowerShell 都行）：

```
pip install -e .
python -m playwright install firefox
```

注意事项：

- **不要带 `#` 注释**。README 里的命令是 bash 语法，Windows cmd 不认 `#`，照抄会报 `Invalid requirement: '#'`
- 第二条装的是 Playwright 专用版 Firefox（约 80MB），不会出现在开始菜单、不影响你日常浏览器
- 安装位置在 `%LOCALAPPDATA%\ms-playwright\`，之前装过 chromium 的会并存，互不影响

## 三、登录 BOSS（只做一次）

```
python boss_firefox.py --login
```

会弹出一个 Firefox 窗口 → 用手机 BOSS App 扫码 → 显示「登录成功」即可关闭。登录态存在本地 `.boss_profile/`，之后不用再登录（失效了重跑这条）。

> ⚠️ `.boss_profile/` 等同于你的账号凭证，**不要打包外发、不要传网盘、不要提交到 git**（已在 .gitignore 中）。

## 四、场景一：采集 JD + 出匹配报告（推荐先跑这个）

> ⚠️ **跑脚本前必须做**：本脚本和 Web 控制台共用同一个 Firefox profile（`.boss_profile/`），**不能同时启浏览器**。
>
> 本版本起脚本会在采集前**主动检测** `http://127.0.0.1:8010/api/status`：如果 Web 控制台浏览器已启动，脚本会立刻打印冲突提示并退出（不会卡到 Firefox 启动失败），按以下任一方式解决：
> 1. Web 控制台「设置」页 → 点击「**停止浏览器**」（只关浏览器，服务还在）
> 2. `Ctrl+C` 关闭 boss_app 服务（连浏览器一起关）
> 3. 改用 Web 控制台完成本次扫描投递，不要跑这个脚本
>
> 反之，脚本跑的时候也别去启动控制台的浏览器。

**第 1 步：准备简历文本**

把你的简历存成一个 txt 文件（纯文本即可，技能、项目经历写清楚），然后导入：

```
python match_report.py --resume-file 我的简历.txt
```

**第 2 步：指定城市 + 岗位，开始采集和分析**

最简命令（全用默认值）：

```
python match_report.py
```

默认配置：关键词 `AI项目经理`、城市 `武汉`、每组合 20 条、全局封顶 50 条 → 实际采 20 条。

带参数的完整命令：

```
python match_report.py --keywords "项目经理,AI产品经理,FDE" --city "武汉,深圳,广州"
```

采集数量规则：**每个「城市×关键词」组合各采 `--per-query` 条**，但全局累计到 `--max-total` 就停。上面例子 = 9 个组合 × 20 = 180 条 → 但 50 条封顶，跑满 50 停。

### 关于 search_kw：岗位归属隔离（重要）

每采集一条岗位，库里都会记下**它是用哪个关键词搜出来的**（`applications.search_kw` 字段）。出报告时按这个字段隔离——**一份报告只分析自己那个 kw 搜到的岗位**。

为什么需要：库里同时存了 `AI项目经理` / `项目经理` / `AI测试` / `FDE` 四个方向的岗位，它们是四个不同岗位。如果不隔离，跑 FDE 报告时会把库里的项目经理、测试岗全拉进来，统计和打分全被稀释。

**推荐做法：一次跑一个 kw，出一份报告。**

```
python match_report.py --report-only --market --keywords "FDE"
python match_report.py --report-only --market --keywords "AI测试"
python match_report.py --report-only --market --keywords "项目经理"
python match_report.py --report-only --market --keywords "AI项目经理"
```

#### 宽词包含窄词（方向性，不可反向）

一个 JD 可能被多个 kw 命中，语义上是**包含关系**而不是对等关系：`AI项目经理` 的 JD 同时也满足「项目经理」的语义，反过来不成立。所以报告会按方向自动展开：

| 跑这个 kw | 实际纳入的 search_kw 池 | 说明 |
|---|---|---|
| `项目经理` | `项目经理` + `AI项目经理` | 宽词分析，包含窄词 JD |
| `AI项目经理` | `AI项目经理` | 窄词**不倒吞**宽词，否则会污染 |
| `AI测试` | `AI测试` | 平行词互不交叉 |
| `FDE` | `FDE` | 平行词互不交叉 |

判定规则：窄词的原文里包含宽词（`AI项目经理` ⊃ `项目经理`），或去掉 `AI/人工智能/智能/数字化` 修饰后核心更长且含宽词核心（`测试开发` ⊃ `测试`）。**只有"更具体"的方向会被包含**，保证不会反向。跑宽词时命令行会打印一行 `[范围]` 提示实际纳入了哪些 kw。

`--search-kw` 可以显式指定分析方向（默认就等于 `--keywords` 的第一个）：

```
python match_report.py --report-only --keywords "AI项目经理" --search-kw "项目经理"   # 用宽词方向分析(纳入 AI 的 JD)
python match_report.py --report-only --keywords "AI项目经理" --search-kw none         # 关隔离, 分析全库
```

采集时的写入是自动的（CLI 采集、Web 控制台搜索、页面扫描都会带 kw），不用手工干预。

**参数速查**：

| 参数 | 作用 | 默认 |
|---|---|---|
| `--keywords` | 岗位关键词，逗号分隔多个 | AI项目经理 |
| `--city` | 城市，逗号分隔多个 | 武汉 |
| `--per-query N` | 每个组合采集条数 | 20 |
| `--max-total N` | 全局封顶（0=不限） | 50 |
| `--include-non-tech` | 把非软件/互联网岗位(建筑/制造/金融/政务等)也纳入统计 | **不开**(默认只统计软件向) |
| `--search-kw` | 报告的分析方向（默认取 `--keywords` 第一个；`none`=关隔离分析全库） | 同 `--keywords` 首个 |
| `--only-new` | 只分析最近 `--new-since-minutes` 分钟内入库的（配合 `--report-only` 复盘单次采集） | 不开 |
| `--new-since-minutes` | `--only-new` 的时间窗口（分钟） | 60 |

运行过程：自动打开 Firefox → 逐组合搜索 → 翻页 → 逐个进岗位详情页抓 JD 全文 → 入库 → 出报告。**没导入简历时自动进入市场模式**（统计 JD 热词，不比对简历）；每个岗位详情约 4 秒，总时长 ≈ 实际采集数 × 4 秒，启动时会打印预估时间。**期间别动弹出的浏览器窗口**。

**第 3 步：看报告**

报告生成在**项目目录 `reports/`** 下，文件名格式 `年-月-日-关键词（城市）[·软件向][·本次N分钟].md`，例如：

- `2026年09月08日-AI项目经理（武汉）.md`
- `2026年09月08日-项目经理（武汉）·软件向.md`（默认）
- `2026年09月08日-项目经理（武汉）·软件向·本次60分钟.md`（默认 + `--only-new`）

> **关于"软件向"标注**：报告标题带 `·软件向` 后缀说明软件向过滤生效——这是**默认行为，不用加任何参数**。判定规则是「标题或 JD 前 500 字命中『软件/互联网/IT/信息化/数字化/SaaS/AI/系统集成/研发/产品/云计算/科技』等词」——搜 `项目经理` / `产品经理` / `FDE` 等宽词时特别有用，避免建筑/制造/金融/政务行业的同名 PM 岗混入统计和打分。想关掉（比如你搜的就是 `政务项目经理` 这种非软件岗），加 `--include-non-tech`。

**报告章节**（每章都把"剔除/过滤"的岗位**完整列出**，方便复核，不再截断丢失）：

- **头部信息**：分析模式 / 岗位数 / 平均分 / 软件向过滤数 / 简历摘要
- **一、市场画像**：薪资中位数 + 分档分布（≤15K / 15-25K / 25-35K / >35K）、经验/学历要求分布
- **二、热门技能词 TOP 30**：每词按公司分组给出 JD 原文要求（HTML `<details>` 折叠展开）
- **三、分类视图**：出现于 ≥20% 岗位的技能按类别聚合
- **四、岗位样本**（**全部显示**，不截断）：按 HR 活跃度排序，应届/校招岗排最后；每条 JD 全文可折叠展开
- **五、已剔除的弱相关岗位**（**全部列出**）：标题不含关键词词根（如 AI 项目经理 → 核心词根"项目经理"）。**开了 search_kw 隔离后这一节通常为 0**——因为报告只看自己 kw 的岗位；如果出现条目，说明该岗位虽属本 kw 池子但标题跑题，值得人工看一眼
- **六、已过滤的疑似无关岗位**（**全部列出**）：标题命中销售/投资/合伙人/猎头等黑名单；可在 Web 设置页 `noise_filter_keywords` 追加
- **七、已过滤的非软件岗位**（**全部列出**，软件向过滤默认开启）：搜宽词时建筑/制造/金融/政务等非软件 PM 岗；加 `--include-non-tech` 后这一节消失
- **匹配模式额外**：二、市场背景补充匹配度≥70 岗位的薪资带对比；三、岗位详情（每岗的差距/建议）；四、关键词缺口分析（简历已覆盖 vs 建议补充）；五、已过滤的非软件岗位

> 告诉你什么：**市场模式** = "市场要什么、值多少钱、够不够格"；**匹配模式** = "你和岗位差在哪、你够得着的薪资带"。

同名文件（同一天+同岗位+同城市+相同后缀）再次生成时**直接覆盖**，每次都是干净的一份最新报告。

**常用变体**：

```
python match_report.py --report-only --market --keywords "FDE"           # 单 kw 一份报告(推荐)
python match_report.py --report-only                                 # 库里已有数据，直接重新出报告（不采集）
python match_report.py --report-only --keyword-only                  # 零成本模式：不调 AI，纯关键词分析
python match_report.py --keywords "..." --city 深圳 --refresh        # 强制刷新已采岗位的 JD
python match_report.py --keywords "项目经理" --city 武汉 --include-non-tech  # 想看全部才加(默认已只留软件 PM)
python match_report.py --report-only --only-new                      # 只看本次入库的（默认近 60 分钟），复盘单次采集
python match_report.py --report-only --only-new --new-since-minutes 30  # 自定义时间窗口
```

> 同名报告**直接覆盖**，重跑即得最新结果，无需手动删旧文件。

**存量数据清洗**：历史入库的岗位如果 `search_kw` 是空的或归类错了（比如按时间平摊分错组），用一次性脚本按标题重新归类：

```
python scripts/refine_search_kw.py            # 预览：打印每条会怎么改，不写库
python scripts/refine_search_kw.py --apply    # 确认无误后写库
```

归类优先级：`FDE` > `AI测试` > `AI项目经理` > `项目经理`；标题命中销售/投资/合伙人/制作/编导等黑名单的会被清空（不进任何报告）。脚本是**一次性**的，不加参数不写库。
**关于 AI Key（本场景）**：采集和两份报告的**统计部分都不需要 AI Key**；只有「匹配报告的逐岗智能打分」受影响——配了 Key 走 LLM 打分（更准，有本地缓存不重复计费），没配自动降级为关键词覆盖率打分，报告结构和章节完全一样，只是打分粒度粗一些。想完全不调 AI 就加 `--keyword-only`。打分时简历摘要会发送给你配置的 AI 服务商。

## 五、场景二：日常搜索 + 投递（Web 控制台）

**第 1 步：启动控制台**

```
python boss_app.py --port 8010
```

浏览器打开 `http://127.0.0.1:8010`（用完记得 Ctrl+C 关掉，减少暴露面）。

**第 2 步：启动浏览器并确认登录**

「设置」页 → 点击「启动浏览器」。首次会要求扫码（同第三章）。

> ⚠️ 如果 match_report.py 正在跑（浏览器窗口在自动采集），**等它跑完再启动控制台的浏览器**——两边共用一个 Firefox profile，同时开必有一边启动失败（报 `Failed to launch the browser process`）。

**第 3 步：配置 AI（可选——先看清楚影响再决定）**

「设置」页 → AI 模型配置 → 选平台（DeepSeek/OpenRouter/MiMo）→ 填 API Key → 保存。

不配 Key，控制台这些功能**照常可用**：搜索、扫描、投递（固定模板招呼语）、聊天记录查看、手动发消息、微信/简历/电话交换。

不配 Key，这些功能**不可用**（点时报错或开不了）：「AI 分析岗位」「AI 简历优化」「AI 沟通建议」按钮、AI 自动回复、智能招呼语（投递时自动回退固定模板，不影响投递本身）。

**第 4 步：搜索 → 投递**

「岗位搜索」页 → 选城市 → 输关键词 → 搜索 → 看中的一键投递或批量投递。

控制台五个页签的分工：

| 页签 | 用途 |
|------|------|
| 🔍 岗位搜索 | 搜索、筛选、投递的主战场 |
| 📋 岗位列表 | 投递记录、状态跟踪（pending/applied/replied） |
| 💬 聊天回复 | 微信风格聊天界面，可开 AI 自动回复 |
| 📱 微信记录 | 已交换微信的汇总 |
| ⚙️ 设置 | 浏览器启停、AI 配置、每日投递上限、简历摘要等 |

**每日投递上限**：「设置」页 → 「每日投递上限」（默认 15，最大 50）。建议新账号从 5~8 起步观察几天。

## 六、场景三：命令行党 / AI Agent 集成

## 七、常见问题（FAQ）

**Q1：pip install 报 `Invalid requirement: '#'`？**
照抄了 README 带 `#` 注释的命令。Windows cmd 不认 `#`，去掉注释部分再执行。

**Q2：playwright install firefox 下载慢/失败？**
重试几次；或设置代理后重试。失败不影响 chromium 已装部分。

**Q3：脚本启动报「未检测到登录态」？**
先跑 `python boss_firefox.py --login` 扫码。登录态失效（几天~几周不等）后重跑即可。

**Q3.5：报 `Failed to launch the browser process` / Firefox 进程秒退？**
浏览器 profile 被占用了——**Web 控制台和 match_report.py 不能同时用浏览器**。本版本起脚本会**主动检测** Web 控制台状态，如果 `browser_running=true` 就立刻打印冲突原因和 3 种解决方案并退出，不会再让你看到这行模糊错误。先关掉一边：到 Web 控制台「设置」页点「停止浏览器」（或直接关掉 boss_app），再跑脚本。反过来，脚本在跑时也别启动控制台的浏览器。

**Q3.6：报告里建筑/制造/金融/政务的 PM 岗怎么还在？**
软件向过滤默认开启，这些岗位会被列到「七、已过滤的非软件岗位」一节（完整可复核），不进统计。如果你确实要它们（比如搜的就是政务项目岗），加 `--include-non-tech`。

**Q3.7：想只看本次入库的岗位（不混历史数据）？**
加 `--only-new --new-since-minutes 60`（默认 60 分钟），只分析这段时间内新入库的岗位。报告标题带 `·本次N分钟` 后缀。配合 `--report-only` 复盘单次采集最合适。

**Q3.8：报告里的岗位样本只显示前 40 个，看不全？**
本版本起已解除截断：「四、岗位样本」显示所有进入统计的岗位、「五、六、七」各剔除/过滤清单也完整列出，不丢岗位。报告文件可能变长，但方便复核。

**Q4：浏览器打开了但采集结果是空的？**
通常是关键词太窄或城市没岗位，换关键词试试；也可能是被风控页拦截，肉眼看一下弹出的浏览器窗口在什么页面。

**Q5：会不会封号？**
批量自动投递 + AI 聊天属于平台协议边缘行为，有风控风险。控制每日投递量（建议 ≤15）、别 7×24 挂机，出「账号异常」提示立即停手休息。

**Q6：我的数据安全吗？**
全部数据（Cookie、JD、聊天记录）只存本地 `.boss_profile/`，代码无任何第三方回传；唯一对外发送是你主动配置的 AI 服务商（简历摘要/聊天上下文）。详见 [README 隐私章节](../README.md#-隐私与数据)。

**Q6.5：`llm_client.py` 在 `interview/` 子目录下，是放错了吗？**
不是。`llm_client.py` 同时被 `match_report.py`（主项目）和 `interview/`（刷题子模块）使用，故意放在子目录里做共享模块；`match_report.py` 启动时通过 `sys.path.insert(0, "interview")` 引入。单文件复用 match_report 时要注意带上这个路径。

## 八、推荐工作流（总结）

```
第一次:    安装 → 扫码登录 → 导入简历 → 4 个 kw 各跑一次报告
日常:      boss_app 控制台 → 搜索投递（每日上限内）→ 聊天页跟进
每周复盘:  删旧报告 → 4 个 kw 各跑一次 → 看匹配度变化调整简历关键词
```

4 个方向：`FDE` / `AI测试` / `项目经理` / `AI项目经理`，**每个 kw 各跑一份报告**：
```
python match_report.py --report-only --market --keywords "FDE"
python match_report.py --report-only --market --keywords "AI测试"
# 项目经理、AI项目经理 同上
```
同名报告直接覆盖，重跑即最新，不用手动删文件。
